# Founder Discipline

> **The weekly ritual that compounds AI conviction in the founder — and prevents the slow, invisible decay back into a pre-AI mental model.**
>
> See `AI_NATIVE_CONSTITUTION.md` (principle 7) and `docs/AI_NATIVE_PLAYBOOK.md` section 9.

---

## Why this exists

The single failure mode the YC playbook warns about, more than any other, is the founder outsourcing AI conviction. "We hired an AI lead" -> the founder stops sitting with the tools -> priors don't break -> the company gradually rebuilds itself like a pre-AI shop, just with AI sprinkled on top, and the original capability gain evaporates within a year.

The defense is a small, weekly, written ritual. It takes 15 minutes. Skipping it kills the principle.

---

## The ritual

Once a week, every week, on the same day (Monday morning works for most people), the founder writes one entry in this file under "Weekly entries".

Entry format:

```
## Week of YYYY-MM-DD

**New capability that landed this week.**
One paragraph. What did I build, ship, or do this week with AI tools that
I either could not have done last quarter or could not have done this fast?
Be specific. Link to the artifact (PR, MemPalace entry, doc).

**Prior that broke.**
One sentence. What did I believe at the start of the week about "what's
possible / how this should work / what would take a team" that I no
longer believe?

**Tool I used most this week.**
Name + 1-line how. (E.g., "Claude Code in agentic loop with project-knowledge
search, building Sprint 1 specs in parallel.")

**Tool I should be using more.**
Name + why I haven't. (Honesty here is the point.)

**Token spend rough estimate.**
$X this week. Reference: docs/Token Budget.md.

**Three-week check.**
- Last week: did I write an entry? Y/N.
- Two weeks ago: Y/N.
- Three weeks ago: Y/N.
If any "N" — schedule a deliberate experiment this week to break a prior.
```

---

## What counts as a "new capability"

Good examples:

- "Generated five SEO blog posts of vertical depth in three hours, where the same task three months ago would have taken a week of writer time."
- "Stood up the entire AI-native foundation pack (constitution, playbook, specs, tests, agents, runbooks) in one session via Claude in chat."
- "Implemented voice AI prompt v2 + Braintrust eval suite + Inngest workflow without writing a single line of code by hand — only specs and scenarios."
- "Designed three vertical landing pages worth of copy + visuals in an afternoon by orchestrating Claude + image-generation + a fact-check loop."

Bad examples (these don't count):

- "Used ChatGPT to write an email." (That's a tool, not a capability gain.)
- "Asked Claude a question." (Asking and getting an answer is the floor, not the ceiling.)
- "Read a tutorial about agents." (Reading is not building.)

The test: would a competent peer founder, hearing what you did, react with "wait, that's possible now?" If yes — that's a capability. If they'd say "sure, I do that too" — you're at the floor and need to push further.

---

## What counts as a "prior that broke"

A prior is a deeply-held belief about how the world works that turns out to be wrong because the tools changed.

Good examples of broken priors:

- "I thought writing 20 SEO posts in vertical depth would require a contractor and four weeks. It took one weekend with the right loop."
- "I thought spec-first development would slow me down vs. just writing code. With agents, the spec is the bottleneck — once it exists, the code generates faster than I can review."
- "I thought we'd need a customer success person before pilot 5. Turns out the AM agent + a queryable inbox replaces the 0-to-5-clients ramp entirely."

Bad examples:

- "I thought AI was useful." (Not specific enough.)
- "I learned a new shortcut." (Not a prior, just a tool tip.)

---

## The three-week rule

If three consecutive weeks pass with **no entry** — or with three entries that say "nothing new this week" — that's a comfort-zone signal. Action: in week four, schedule a deliberate experiment that's likely to break a prior.

Deliberate experiments look like:

- "Build feature X end-to-end without writing any code by hand. Spec + scenarios + agent only."
- "Run an entire sales call cycle (prep, call, follow-up, deal docs) with AI in the loop end-to-end."
- "Try a tool I've heard about but haven't used (e.g., a new agent framework, a new IDE-integrated agent, a new evaluation tool)."
- "Spend a full day with token spend uncapped to see what the ceiling actually is."

The point isn't the experiment per se. The point is breaking the unconscious assumption that this week will look like last week.

---

## Sharing with the team (when there is one)

When the company has a team, the weekly entry is posted in a Slack channel (`#founder-discipline` or similar) for the team to read. This anchors the team's expectation of what's normal: the founder ships visible AI-leveraged work every week. Anyone who can't show similar capability gains over a quarter is in the wrong company.

Until there's a team: the entries here are written for future-you and for any agent that searches this file for context.
