# Markdown report writer

> Long-form, human-friendly markdown report. Suitable for embedding in PRs, issue trackers, or static-site renders. One section per module with full evidence tables, plus a methodology pointer + scoring-version footer for citation provenance.

---

## 1. Goal

`reports::markdown_report::write(report, path)` writes a self-contained `.md` file that a maintainer can open in any markdown renderer (GitHub, VS Code, mdBook) and understand without context. Includes inline citations to `docs/methodology.md` for each module.

We know it works when: the produced markdown round-trips through `pulldown-cmark` (no malformed syntax) and the insta snapshot matches a known-good fixture for the inactive `octocat/Hello-World` baseline.

---

## 2. Non-functional requirements

- **GitHub-flavored:** tables use pipe syntax; headers use `## H2` / `### H3`; code spans for module names + sub-score keys.
- **Determinism:** byte-identical output for the same `TrustReport` modulo `snapshot_at` + `runtime_seconds`.
- **No new runtime crates:** plain string formatting; no markdown-builder library.
- **Embeddable:** report fits in a single GitHub issue body (<65k chars) for the typical 5-module run.

---

## 3. Boundaries

### In scope (Day 4)
- `src/reports/markdown_report.rs::write(report: &TrustReport, path: &Path) -> Result<()>`.
- Header section: `# Trust Report — {full_name}` + summary block (score, category, confidence, mode, scoring_version, snapshot_at, runtime_seconds).
- One `## {Module Name}` section per module with: score badge line, sub-scores table, evidence table (code, label, value, threshold, verdict, rationale), missing_data list.
- "Top Strengths" + "Top Concerns" sections.
- "Caveats" section when populated.
- "Methodology" footer linking to `docs/methodology.md` and the specific scoring version.
- ≥4 unit tests + 1 insta snapshot.

### Out of scope
- Embedded charts (sparklines, histograms) — Day 5+.
- HTML render (web viewer is its own surface).

## 6. Architecture sketch

```
write(report, path):
  1. open file
  2. write_header(report.repository, report.overall_*)
  3. for module in report.modules:
       write_module_section(module, evidence_for_module(report.evidence, &module.module))
  4. write_strengths_concerns(report)
  5. write_caveats(report.caveats)
  6. write_footer(scoring_version)
```
